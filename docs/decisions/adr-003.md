# ADR-003 — API vs SPI

**Status:** Accepted

**Decision:** separate artifacts and packages for consumer API and extender SPI; SPI exists only
when ≥ 2 providers are plausible.

**Why:** different audiences evolve at different speeds and need different compatibility promises;
merging them forces the slowest evolution speed on everything.

**Consequence:** more modules; crisp compatibility contracts; extenders never see internals.

See also: [extension model](../concepts/extension-model.md) · [conventions](../concepts/conventions.md).
