# ADR-006 — Module boundaries by capability, layered inside

**Status:** Accepted

**Decision:** vertical capability slices, each internally split api/spi/impl/autoconfigure/starter;
every module in exactly one category (§2.2).

**Why:** ownership, blast-radius control, and classpath minimalism follow capability lines, not
technical layers.

**Consequence:** many small modules; mitigated by scaffolding plugin and build caching.

See also: [architecture](../concepts/architecture.md) · [dependency constitution](../concepts/constitution.md).
