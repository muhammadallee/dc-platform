**New concern from the proposed F2 fix:** With separate Flyway credentials and `spring.flyway.locations=classpath:db/migration/{vendor}`, Boot calls `configureProperties()` → `LocationResolver.getDatabaseDriver()` → `JdbcUtils.extractDatabaseMetaData()` **before returning the Flyway bean**. A silent Oracle peer can therefore block before its post-processor executes. Apply the bounds before this metadata connection and test this configuration; replacing the migration strategy with a no-op does not bypass location resolution. See [Boot’s `FlywayAutoConfiguration`, lines 139–152, 202–204 and 385–391](https://raw.githubusercontent.com/spring-projects/spring-boot/v4.1.0/module/spring-boot-flyway/src/main/java/org/springframework/boot/flyway/autoconfigure/FlywayAutoConfiguration.java).
