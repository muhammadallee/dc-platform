# Data access (Oracle) — sample

## What it solves

A service that stores its data in Oracle gets, without writing any of it:
- **one dependency** that brings the JDBC driver and Flyway's Oracle module together
  (`platform-starter-data-jpa-oracle`), and a generator option that selects it;
- **bounded waits**: a request never waits more than 5 s for a pooled connection, a transaction more than
  30 s, and the driver never waits more than 60 s for an answer. A slow or lost database becomes a fast,
  retryable **503** instead of piled-up request threads;
- **problem responses for data errors**: a unique, foreign-key, NOT NULL or check violation is a **409**, a
  concurrent update a **409** with its own code, an unavailable database a retryable **503**. The body never
  names SQL, tables or constraints; the full exception is logged once on the request's trace;
- **safe migrations**: Flyway never cleans a database, validates before migrating, rejects misnamed files,
  and refuses out-of-order migrations outside the `local` profile.

## When to use / not use

- **Use** it for every service whose production database is Oracle (prod runs 19c; HD13).
- **Do not** use it for another database: only Oracle is certified. A service on another database keeps
  `platform-starter-data-jpa` and must add that database's driver **and** `flyway-database-<db>` itself.
- **Do not** let the service own its schema: run Flyway as a schema-owner user and the service as a runtime
  user without DDL rights (below).

## Minimal real setup

Generate the service with the Oracle option (exact command in [`commands.md`](commands.md)):

```bash
mvn org.apache.maven.plugins:maven-archetype-plugin:3.1.2:generate -DinteractiveMode=false \
  -DarchetypeGroupId=ae.gov.dubaicustoms.platform -DarchetypeArtifactId=platform-service-archetype \
  -DarchetypeVersion=<platform version> -DgroupId=<group> -DartifactId=<service> -Dpackage=<package> \
  -Dfeatures=data -Ddatabase=oracle
```

H2 still backs local runs and tests. In `prod`, supply the coordinates from the environment or the secrets
source (never in `application.yml`). The consumer run used exactly these:

```properties
SPRING_PROFILES_ACTIVE=prod
SPRING_DATASOURCE_URL=jdbc:oracle:thin:@//db-host:1521/APP_SERVICE
SPRING_DATASOURCE_USERNAME=APP_RUNTIME
SPRING_DATASOURCE_PASSWORD=<secret>
# Relaxed binding drops the dashes: CONNECTION_INIT_SQL would bind a different property and fail startup.
SPRING_DATASOURCE_HIKARI_CONNECTIONINITSQL=alter session set current_schema=APP_OWNER
SPRING_FLYWAY_USER=APP_OWNER
SPRING_FLYWAY_PASSWORD=<secret>
```

The schema owner owns the tables (`create table/sequence/view`); the runtime user has `create session` and a
role with `select/insert/update/delete` on them, granted **by a migration**, so a deploy needs no manual
step:

```sql
-- V2__orders.sql (runs as APP_OWNER; 19c-safe)
create table orders (
    id         numeric(19) generated by default as identity primary key,
    reference  varchar(64) not null,
    placed_at  timestamp with time zone not null,   -- Instant fields: WITH TIME ZONE (D114)
    constraint uq_orders_reference unique (reference)
);
grant select, insert, update, delete on orders to app_rw;
```

## Walkthrough

1. **Startup.** Flyway connects as the owner (its own connection, with the Oracle connect timeout and a
   10 min read timeout so a long migration statement can finish) and applies `V1…`, `V2…` in order. The
   service then reads and writes the owner's tables as the runtime user, through `CURRENT_SCHEMA`.
2. **A request.** Repository methods run in a transaction of at most 30 s; a query outside one is bounded at
   30 s too. On a lost or slow database the request ends as `503 DC-DATA-0503` (`retryable: true`) within the
   connection timeout, the transaction timeout or, at worst, the 60 s driver read timeout.
3. **A conflict.** Inserting a duplicate `reference` returns `409 DC-DATA-0409` with the request's `traceId`
   and a fixed detail; the platform's WARN on that trace carries the ORA- message for operators.
4. **Shutdown.** On SIGTERM an in-flight transaction completes and commits, the pool closes, the JVM exits
   with 143.

Oracle specifics (`''` is NULL, no `BOOLEAN` in 19c, `Instant` columns, identifier length) are in
[`../../modules/data.md`](../../modules/data.md). See [`verification.md`](verification.md) for what was proven,
[`operations.md`](operations.md) for running it, [`troubleshooting.md`](troubleshooting.md) when something
